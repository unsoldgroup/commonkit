# The Session Board never decides; absence never blocks

Every allow, deny, or option selection that flows through the Session Board is a human tap on the board UI; no board component computes or infers a decision. The Claude hook registers under the PermissionRequest event and stays fail-open: on timeout, hub outage, reporter outage, malformed payload, or any error it returns no decision, so the agent's normal terminal prompt appears exactly as if the board did not exist. Codex injection sends an explicit option number only after a read-verify step confirms the prompt is still on screen, and Orca gates resolve only through `gate-resolve` carrying a human verdict. The consequence is deliberate: a dead or unreachable board can never approve anything and can never prevent the human from being asked; the board is a faster path to the same human, never a substitute. Automation that removes the human from a specific pattern must happen in the permission configuration itself (allowlist rules), where it is durable, auditable, and visible in the repo or home directory, not in the board's decision path.
