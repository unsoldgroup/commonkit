# Encrypt personal context before GitHub

CommonKit treats a user's private GitHub repository as an untrusted ciphertext store: personal values are encrypted locally and decryption identities never enter GitHub or organization storage. Personal context uses partially encrypted structured files with canonical schema field names visible so Git history remains reviewable and agents can discover relevant categories before authorization; this deliberately leaks field and section presence, edit timing, and approximate value sizes. The schema is closed and unknown fields fail closed. Each user controls two independent recovery paths—an offline recovery key and an encrypted recovery identity provisioned through their password-manager provider—so routine device loss is recoverable without granting the organization access to the complete profile.

Deletion is necessarily bounded by that recovery design: CommonKit revokes future use and removes active controlled copies, caches, grants, and key envelopes after a signed tombstone is observed, but it cannot claim cryptographic erasure of historical Git ciphertext from clones or backups held together with a formerly valid recovery identity.
