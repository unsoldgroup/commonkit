# Separate portable configuration from mutable state snapshots

CommonKit uses a GitHub repository as the durable store for versioned configuration, policy, capabilities, and content-addressed snapshot descriptors. Creating a snapshot uploads both the encrypted database and encrypted manifest to S3-compatible object storage before atomically publishing its descriptor into the configured Git-kit directory. A receiving machine can therefore discover and authenticate the manifest from Git plus object storage while snapshot keys and plaintext remain target-provisioned. A local CommonKit service powers the CLI, macOS status bar, and MCP tools as peer interfaces. Mutable SQLite databases are never synchronized through Git, and version 1 assigns one authoritative writer per database to avoid unsafe binary merges and ambiguous conflict resolution. Writer promotion is authorized only from consistent database observations performed by CommonKit; request assertions cannot stand in for target evidence.
