# "Allow always" writes project-local rules with a previewed pattern

The board's Always verb persists an allowlist rule to `<session cwd>/.claude/settings.local.json` on the machine that owns the session, never to the global `~/.claude/settings.json`. Rules are derived, not free-form: Bash commands become a subcommand-prefix rule (`Bash(git push:*)` — first token, or first two for multi-command tools like git/npm/pnpm/gh), and file tools become tool-scoped rules for that project. The exact rule text is shown on the card before it is written. Persistence happens through Claude Code itself: the hook's allow decision carries the rule in Claude Code's documented rule-persistence field (`ruleSuggestions` or `updatedPermissions` with destination `localSettings` — pin the exact shape against current docs at implementation, UNS-1330), the same mechanism the terminal's "don't ask again" uses, so no board component ever edits a settings file directly. Trade-off accepted: the same pattern will re-prompt in other repos, costing extra taps, in exchange for a blast radius bounded to one project, rules that are reviewable in that repo's own working tree, and no board-originated mutation of global agent behavior. This is the only place the board touches configuration, and it still never decides a live prompt (ADR 0008); it only records that the human no longer wants to be asked.
