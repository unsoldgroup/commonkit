# An investigation reports; it never writes to the repository

When a **Declared task** fails, CommonKit can dispatch a coding agent to the **Execution Target** that produced the failure, inside the retained workspace, driven through the existing `ImplementorAdapter` contract as an ordinary **Job**. The agent inherits that target's **Loadout**, so it investigates with the same skills, hooks, and instructions the developer's own agent would have — which is the point, and is not reproducible by shipping logs to a laptop. Its output is findings committed as a signed artifact, optionally a proposed patch as a second artifact, and nothing else: `repositoryWrite` stays false, the execution policy's `allowRepositoryWrite` stays false, and no push credential is ever provisioned to a target whose job is to run untrusted repository code. Rejected: letting the agent commit and open a pull request, which is more useful exactly when the agent is right and unbounded exactly when it is wrong, and which would require reversing a boundary the policy enforces at both submission and execution and asserts in tests. A patch that is inert data until a human applies it on their own machine preserves the property that a CI target can produce evidence and analysis but can never author history. The consequence accepted is a manual step between a correct diagnosis and a merged fix; the alternative buys convenience with the one credential we have most reason to withhold.
